# Found #40: binding-pattern parameter types order a union differently

## Result (default work-stealing, `--checkers 2`, 200 runs)

| output | runs | rate |
|---|---|---|
| `g1/use3.ts(5,14): TS2322: Type '{ a: any; b: any; } \| { c: any; d: any; }' ...` | 83 | 41.5% |
| same error with `'{ c: any; d: any; } \| { a: any; b: any; }'` | 117 | 58.5% |

Both outputs (including the emitted `.d.ts`) are in `outputs/`.

## Program (`g1/`)

```ts
// decl.ts
export function f1({ a, b }) { return 1; }
export function f2({ c, d }) { return 1; }
export function f3([e, g]) { return 1; }
export function f4([h, i]) { return 1; }
export declare const flag: boolean;
// use3.ts
import { f1, f2, f3, f4, flag } from "./decl";
type P1 = Parameters<typeof f1>[0]; type P2 = Parameters<typeof f2>[0];
type Q1 = Parameters<typeof f3>[0]; type Q2 = Parameters<typeof f4>[0];
declare const x: P1 | P2; declare const y: Q1 | Q2;
export const n1: number = x;
export const n2: number = y;
// pad0.ts: type PA = Parameters<typeof f2>[0]   (the "poison")
// pad1..3.ts: reference f1 only
```

## Why

The types of untyped destructured parameters (`{a,b}` vs `{c,d}`) have no symbol, so
`compare_types` ties on them and falls back to type creation id. Whichever checker
resolves `f2`'s parameter type first (pad0 before use3 on the same checker) prints
`{c;d} | {a;b}`; otherwise `{a;b} | {c;d}`.

## Scheduling setup

Every pad imports decl.ts, which moves the core files to the back of the queue.
Only pad0 touches f2. Whether use3's checker ran pad0 first is a timing/steal race.
tsconfig needs `rootDir: "."`. Large ghost comments (generated by gen2) equalise pad cost.

## Reproduce

```
node ..\_harness\run.js . --mode steal --runs 200 --checkers 2
```
